## 一、这一分钟在画什么（节拍表）

| 时间 | 旁白 | 画面动作（锚定的字） |
|---|---|---|
| 0–4s | 给对象发了条消息，半小时没回 | 一笔一笔画出手机、聊天界面；「发了条消息」时气泡「晚上一起吃饭？」出现；「半小时」时镜头拉开，左边画出一只钟，分针扫过 30 分钟，扫过的扇形用淡红色填上。手机顶上的时间 20:14 也跟着变 |
| 5–9s | 拿起手机看了一眼，放下，又看一眼 | 手机屏幕在「亮屏看时间 → 熄屏 → 再亮屏」之间切换，锁屏上写着「没有新消息」；左边「看了 N 次」的计数，同时用画「正」字的方式一笔一笔记，每一笔配一声轻点 |
| 9–13s | 补了一句「在忙吗？」，还是没回 | 输入栏里逐字打出「在忙吗？」，发出；对方那一侧只画出一个虚线的空气泡，里面是「……」 |
| 13–18s | 点开朋友圈，十分钟前刚给别人点过赞 | 镜头横移到第二部手机，画出朋友圈：头像、图片、「10分钟前」被红笔圈出，下面是「♡ 阿哲」，再圈一次 |
| 18–20s | 好，这下火上来了 | 镜头拉远看全景：两条红箭头从两部手机出发（「半小时不回」「却有空点赞」），汇到中间，画出一团排线的火，火苗每几帧换一版在闪 |
| 20–22s | 先别急着评理 | 火的上方画出一架天平，两个秤盘写「他不在乎 / 我太敏感」，摆了几下，然后被红笔打叉 |
| 22–25s | 把这件事拆成三层看 | 镜头移到纸的下半部，画出三条「地层线」，标上 ①②③ |
| 25–34s | 事情：他回消息慢；你的反应：反复看、追问、找证据 | 「事情」「你的反应」按真实笔顺一笔一笔写出来；第一层画小手机 +「他回消息慢」；第二层依次画「正」字 + 反复看、「在忙吗？」气泡 + 追问、放大镜（里面是一颗心）+ 找证据，每个都锚在对应的词上 |
| 35–42s | 最底下一层才是真正在起作用的东西：你想确认我在他那儿是重要的 | 第三层用琥珀色排线一根根铺满；三根琥珀箭头从底层往上顶到第二层的三个反应；镜头推近，出现母题「琥珀圆点」，写出「我在他那儿是重要的」 |
| 42–45s | 书里管这层叫需要 | 拉回三层全景，「需要」用琥珀色按笔顺写出并圈起来 |
| 45–52s | 没照顾到，换一个人、换一份工作，它还会换个样子再冒出来 | 琥珀圆点暗下去；三条地层线向右延长出两列：上两层换成「朋友已读不回 / 一遍遍点开对话框」「领导没回我的方案 / 反复刷新邮箱」，**最底层还是同一条琥珀带**；拉远看三列，三个圆点依次重新亮起，三个「是重要的」下面画同一道琥珀线 |
| 52–55s | 不劝你「别想太多」 | 镜头上移到大字「别想太多」，一道有粗细变化的红笔划掉 |
| 55–60s | 就做一件事：把三层一层一层画清楚 | 右边两列和「别想太多」擦掉，回到第一列；三层各框一个框（最底层是琥珀色框），顶上写「这期：把三层，一层一层画清楚」，琥珀笔迹下划线 |

画面状态大约每 3–6 秒变一次，每 15–20 秒换一个段落（故事区 → 三层图 → 三列对照 → 回收），全片没有一处「背景 + 字幕」。

## 二、设计系统

**纸和墨**
- 纸：暖白 `#F6F1E6`，2048² 可无缝平铺的纸纹（低频明暗 + 颗粒 + 纤维，numpy 频域滤波生成，固定种子）。纸纹跟着镜头一起平移、缩放，所以镜头动的时候像在移动一张真的纸，而不是在固定背景上滑动图层。四周一圈很淡的暗角。
- 颜色只有四种，各有职责：
  - 墨 `#2A2622`：所有主线条和正文。
  - 铅笔灰 `#A0988C / #7C746A`：辅助说明（「发生了什么」「你做了什么」）、次要界面线。
  - 红 `#C9492E`：情绪和否定，只用于圈证据、火、打叉、划掉。一集用几次，多了就不值钱。
  - 琥珀 `#E49B2F`（字用深琥珀 `#8A5210`）：**只给「需要」这一层**。这是全季母题的颜色，见第五节。
- 不用 emoji，不用贴纸剪贴画，所有图形都是在画面里画出来的。

**字体**
- 画面手写：霞鹜文楷 Medium（LXGW WenKai v1.522，SIL OFL 1.1，从官方 GitHub releases 下载），按本集用到的 599 个字子集化成 254 KB（`tools/subset_font.py`）。只烧进画面，不分发字体文件。
- 关键词：不用字体，用 `hanzi-writer-data` 的真实笔顺数据**一笔一笔写出来**（事情 / 你的反应 / 需要）。
- 阅读字幕：思源黑体 Noto Sans SC 46px，中灰黑，居中一行，放在画面最下面 150px 的字幕区；画面内容区只用上面 894px，镜头取景时就把字幕区算在外面，字幕上方还有一道纸色渐隐，所以画面永远不压字幕。关键词念到时变深琥珀色，下面扫出一道琥珀色的记号笔。

**线条**
- roughjs 只用来「算形状」（固定 seed），再拆成折线，逐帧只画出前 p%，所以每一笔都有真实的书写方向和速度；roughjs 的双线，第二笔比第一笔晚一点起步。
- 画完的线每 9 帧在两个版本之间切换（「线条呼吸」，约 3 次/秒），画面静止时也是活的，但不晃眼。
- 线宽随镜头缩放做补偿（`z^-0.6`），拉远时线不会细到看不见，推近时也不会粗成马克笔。
- 排线填充（火、琥珀层）是一根一根扫出来的；火的排线每 3 帧换一版，做出闪动。
- 强调线（最后的下划线、划掉「别想太多」）用 perfect-freehand，起笔重、收笔轻。
- 画面上有一支铅笔，笔尖始终跟着正在画的那一笔走；两笔之间笔会抬起、滑过去；间隔长就离开画面。

**镜头和运动规则**
- 整集是一张大纸（世界坐标约 3600×2300）：上半张是「故事区」，下半张是「三层图」，右边往外长出两列对照。画过的东西都留着，最后回收时才擦掉一部分。
- 镜头关键帧写成「要看的框」（世界坐标矩形），渲染器自动算出缩放和中心，保证框落在字幕区以上。
- 镜头插值：缩放在对数空间插值（推拉匀速），缓动先慢后稳；到位后每秒再慢慢推近 0.45%（最多 3%），加一点点手持漂移（噪声），所以停住的画面也不是死的。
- 大的移动（换区域）配一声很轻的风声；「正」字每一笔配一声轻点；笔在纸上时有铅笔沙沙声（音量按「笔是否在画」逐帧开关，前后平滑）。音效全部 numpy 合成（`tools/make_assets.py`）。
- 所有动画由 `useCurrentFrame` 推出的毫秒数驱动，没有 CSS 动画、没有 `Math.random`，任意一帧可以单独复现。

## 三、场景词汇表（可复用组件）

所有组件的约定：坐标是世界坐标；`t0` 是开始落笔的毫秒；往「分镜板」`Board` 上加一组带时间的条目，渲染器逐帧画。`o` 里通用的选项有 `color / w（线宽）/ out（何时擦掉）/ g（属于哪个变换组）/ pen（笔要不要跟着）`。

**引擎层动词**（`engine/`）

| 动词 | 调用 | 说明 |
|---|---|---|
| Draw | `b.stroke(seed => R.xxx(...), t0, dur, o)` | 任意 roughjs 形状（线、曲线、圆、椭圆、矩形、任意 SVG path）描出来 |
| Hatch | `b.fill(seed => R.hatchRect/hatchPath(...), t0, dur, o)` | 排线填充，一根根扫出；`flicker` 让它闪（火） |
| Hand | `b.text(s, x, y, size, t0, o)` | 手写体一句话，从左往右擦出；笔跟着写 |
| Write | `write(b, word, x, y, size, t0, dur, {color})` | 真实笔顺逐笔写词（中线遮罩 + `evolvePath`），笔间停 45ms、字间 110ms |
| Freehand | `freehand(b, pts, t0, dur, {size, color})` | 有粗细的笔迹 |
| Node | `b.node(t0, (ms, frame) => JSX)` | 任何随时间变化的东西（数字、屏幕状态、扇形） |
| Group | `b.groups[id] = ms => transform` | 让一组笔画一起动（天平摆动、分针转动） |
| Camera | `b.cam(t, [x0,y0,x1,y1], dur, whoosh)` | 看哪个框 |
| Erase | `b.eraseAll(b.since(mark), t, dur)` | 把一批东西擦掉 |
| Cue | `q.at('词') / q.end('词') / q.ch('词', k)` | 从逐字时间里找到「念到这个词第一个字 / 念完 / 第 k 个字」的毫秒——所有调度都挂在字上，改稿后只要词还在就会自动对齐 |

**场景组件**（`kit.tsx`，这一季反复会用到的东西）

| 组件 | 参数 | 用途 |
|---|---|---|
| `phone` | x, y, w, h, t0, dur → 返回屏幕矩形 | 手机外框、听筒、屏幕 |
| `bubble` | x, y, w, h, t0, {side, text, dashed} | 聊天气泡；`dashed` 画「本该有却没有」的回复 |
| `clock` | id, cx, cy, r, t0, minute(ms) | 钟：分针转动、扫过的时间涂成扇形；和屏幕上的时间读同一个函数 |
| `zheng` | x, y, size, times[] | 画「正」字计数，每一笔一个时刻 |
| `flame` | cx, cy, s, t0 | 火：描边 + 闪动排线 + 内焰 |
| `balance` | id, cx, top, L, t0, tilt(ms), [左, 右] | 天平：横梁按函数摆动，秤盘始终竖直 |
| `magnifier` | cx, cy, r, t0 | 放大镜（里面一颗心）＝「找证据」 |
| `miniPhone` | x, y, s, t0 | 小手机图标 |
| `arrow` | a, b, t0, dur, {bend, head} | 手绘弯箭头 |
| `ring` / `under` | 形状 + t0 | 红圈、下划线（标注） |
| `badge` | cx, cy, r, '1', t0 | 画圈的序号 |
| `stratum` | x0, x1, y, t0, dur, {phase} | 地层线（三层图的骨架） |
| `seed` | cx, cy, r, t0, glow(ms) | **母题：琥珀圆点（需要）**，亮度随时间变化 |

## 四、怎么扩展到 10 分钟和任意稿子

流水线：**稿子 → 节拍表 → 分镜数据 → 场景组件 → 渲染 → 印样自检**。

1. **稿子 + 配音 + 逐字时间**（每期重做，已有流程）：`script.txt → audio.mp3 → captions.json`。
2. **节拍表**（每期重做，最重要的一步）：两栏，左边旁白原句，右边「动词 + 对象 + 锚定的词」。例如「半小时没回 → clock 分针扫 30 分钟，锚『半小时』」。写不出画面动作的句子，说明这句太虚，要回去改稿。这一步应该先给你看，确认后再写代码。
3. **分镜数据**：现在的 `lab01.board.tsx` 本质上已经是数据——每一行都是「在某个词上，用某个组件，画在某个位置」。下一步把它抽成 JSON：
   ```json
   {"cue": "半小时", "verb": "clock", "at": "B2", "args": {"sweep": 30}}
   {"cue": "需要", "verb": "write", "at": "A5", "args": {"color": "amber"}}
   {"cue": "换一个人", "verb": "camera", "frame": ["F4", "L6"]}
   ```
   位置用锚点网格（每个 1920×1080 的「一屏」切 6×6），agent 说「B2」而不是写像素；渲染前自动检查有没有重叠、有没有出取景框。10 分钟的片子就是一张很大的纸，每个段落占一块「岛」，段落之间镜头移过去，前面画的保留，章末拉远看全貌。
4. **组件库**（整季复用，偶尔新增）：上面的动词和组件。每期大约 70% 的画面靠已有组件拼出来，另外每期新做 2–3 个这一期专属的道具（本期是天平、朋友圈）。新组件做完就进库。
5. **自检**（每期跑）：`tools/stills.mjs` 一次打包渲染若干关键帧，`tools/sheet.py` 拼成带时间标签的印样；全片渲染后按每秒一帧出印样。可以再加 ffmpeg `freezedetect` 找超过 8 秒没变化的段落。

每期要重新做的：稿子、节拍表、分镜数据、2–3 个专属道具、`write` 用到的新关键字（在 `verbs.tsx` 里 import 对应的 hanzi 数据）、字体子集（重跑一次脚本）。
不用重做的：纸、配色、字幕、镜头、笔、音效、三层图和母题、整个渲染引擎。

## 五、视觉母题：三层地层 + 琥珀圆点

- **三层地层**（事情 / 反应 / 需要）是这一季的地图。每一集都会回到这张图上，只是往里填不同的东西。
- **琥珀色只属于「需要」**。只要画面上出现琥珀色，观众就知道在说最底下那一层；圆点亮着 = 需要被照顾到，暗下去 = 没被照顾到。
- 在后面的集数里怎么生长：
  - 每一集讲一种需要（被重视、安全感、被认可……），就在底层种下一颗新圆点，写上它的名字。季中回顾时拉远，底层已经是一排圆点。
  - 「换一个人、换一份工作，同一个需要冒出来」这种三列对照，可以变成固定段落：每集末尾用它把本集的需要放到三个生活场景里验证一遍。
  - 讲到「照顾需要」的方法时，圆点从暗到亮就是这一集的收尾动作；季末所有圆点一起亮起来。
  - 以后如果加「小人」母题，小人站在第二层（反应层），脚下连一根线到底层的圆点。

## 六、自评

**做得好的**
- 画面在讲内容：钟的扇形就是「半小时」，「正」字就是「看了几次」，虚线空气泡就是「没回」，被圈出来的「10分钟前 / ♡阿哲」就是证据，两条红箭头汇成火就是「火上来了」。三层图里，三根琥珀箭头从底层顶上去，直接画出了「底层才是真正在起作用的」。关掉声音也能看懂一大半。
- 「换一个人、换一份工作」做成了三列对照：上面两层内容全换，最底层是同一条琥珀带、同一个圆点、同一道下划线，这是本片最有说服力的一个画面。
- 手作感是真的：每一笔有方向和速度，关键词按真实笔顺写，笔跟着走，有沙沙声，线条在呼吸；不像把图片淡入。
- 大纸 + 镜头，画过的东西保留，最后回收到三层图上，有白板讲解的连续感，不像翻 PPT。
- 所有调度都挂在字上，换配音后重新跑逐字时间就能自动对齐。

**不够的**
- 三层图段（25–45 秒）文字偏多。「发生了什么 / 你做了什么」「（半小时没回）」这些小字其实可以删，让图更干净。
- 拉远到三列全景时（49–53 秒），列里的字在手机上会偏小（约 28px）。
- 情绪段（火）只有 2 秒，全景里火不够大。可以在「火上来了」时推近到火上，再在「先别急着评理」时拉开。
- 22–25 秒从故事区下移到三层图时，两块之间没有视觉上的连接（比如把整段故事缩成一个小图标带进第一层），转场偏硬。
- 没有「参与式钩子」：参考片第一句就让观众自己补字，我们第一句「你有没有过这种时候」只画了一部手机。
- 占位配音语速快，很多动作只能压在 0.5–1 秒里完成；换成真声以后节奏会更从容，需要重新检查一遍。
- 世界坐标还是手写像素，没有用 6×6 锚点网格，也没有自动的遮挡检查。

**下一步最该改的**
1. 把 `lab01.board.tsx` 抽成「节拍表 JSON + 锚点网格」，加遮挡 / 出框检查，让写下一期的 agent 只写数据不写坐标。
2. 三层图减字：每层只留「标题 + 1 个图标 + 1 句话」，小字全部删掉。
3. 加一个段落间的转场动词（把上一段缩成缩略图，带进下一段），解决段落之间的硬切。
4. 开头加一个参与式钩子：比如先画出空的「已读」和一个跳动的时间，让观众先产生「他怎么还不回」的感觉。

## 0. 先说结论

1. **参考片的差距不在技术栈。** 电子智人那条片子，按目前所有公开资料看，就是“Opus 写代码 → 每一帧是时间 t 的纯函数 → 无头浏览器逐帧截图 → ffmpeg 合成”。Remotion 的 `useCurrentFrame()` 本来就是这套机制，而且更成熟。我们差的是两件事：**文案和画面没有一起设计**，以及**没有一套能被每句话复用的手绘“动词”**（画出来、圈出来、划掉、写出来、推镜过去）。换渲染器解决不了这两件事。
2. **Agent 做视频的开源方案，好的那几家结构都差不多**：先出“节拍表/分镜”并让人确认，再只做一个样板镜头确认风格，然后逐镜实现、分段渲染，最后用“印样（contact sheet）+ 独立审片 agent + 机器检查”把关。这套流程可以直接照搬到我们的 Remotion 工程里，不需要装任何人的 skill。
3. **手绘层要补的库很少**：`@remotion/paths`（`evolvePath` 描线）、`perfect-freehand`（有粗细变化的笔迹）、`hanzi-writer-data`（汉字真实笔顺，能一笔一笔写出关键词），再加霞鹜文楷或“小赖”手写字体。都是 MIT 或 OFL 这类可商用许可，Windows 上是纯 JS 数据，没有环境风险。
4. **配音**：占位配音建议从 edge-tts 换成**用你自己声音克隆的本地模型**（Qwen3-TTS 或 CosyVoice 3，都是 Apache-2.0，权重也是），这样排节奏时的语速和停顿更接近你的真录音。**发布仍然用真声**；如果要用克隆声发布，就必须做 AI 标识。F5-TTS、Spark-TTS、Fish S2 的权重都是非商用许可，排除。
5. **炒作的部分**：“一句话生成整条片子”没有任何人公开过完整会话记录；星数很高的 skill 目录（180+ 个仓库）大部分是英文竖屏带货模板；几个做得最好的中文口播 skill 用的是**非商用许可**（PolyForm Noncommercial），只能学思路，不能拷代码。

## 1. 对我们下一版最有用的 5 件事

按“投入小、对观感提升大”的顺序排。每件事都标了借鉴的出处，具体做法在后面的章节里。

### ① 文案和画面写在同一张表里：“节拍表”先行，先确认，再写代码

- **做什么**：每期稿子不再是一段纯文字，而是一张两栏表：左边是旁白原句，右边是这句话的“画面动作”（动词 + 对象 + 锚定的那个字）。比如「他**半小时**没回」→ 时钟指针转半圈，锚在“半”字；「你看了**第七次**手机」→ 计数器从 1 跳到 7，锚在“七”字。写不出画面动作的句子，说明这句话太虚，要么改写成具体的，要么删掉。这条同时回答了你对文案的意见：**逼着每一句都落到可以画出来的具体事物上**。
- **流程关卡**：Agent 先交节拍表和 4 张关键帧的静帧，你点头之后再写动画代码。这是 Hugging Face 上那篇 Opus 5.5 做视频教程里的原话做法（“先回节拍表和 4 张关键帧，我批准后再写文件”），也是 video-talkcraft 从 2026-09-09 起改的规矩（“首镜先做先确认”）。
- **出处**：[HF 博客：Opus 5.5 确定性渲染流水线](https://huggingface.co/blog/karmen-beatapi/how-to-make-videos-with-claude-opus-5-5)、[video-talkcraft](https://github.com/Vincentwei1021/video-talkcraft)（SHOTBOOK 分镜、语义拍）。

### ② 建一套手绘“动词”组件库，整季复用

十个左右的原语就能覆盖大部分画面动作，每个都由帧驱动、可以复现：

| 动词 | 实现 | 用在哪 |
|---|---|---|
| 画出来 `Draw` | roughjs 生成路径 → `@remotion/paths` 的 `evolvePath(progress, d)` 描线 | 方框、箭头、简笔小人、手机、时钟 |
| 写出来 `Write` | `hanzi-writer-data` 的笔画轮廓加中线，按真实笔顺逐笔露出 | 关键词（“需要”“安全感”）一笔一笔写上黑板 |
| 圈出来 / 划重点 / 划掉 `Annotate` | 照 rough-notation 的形状算法，用 roughjs 画、`evolvePath` 驱动 | 圈住一句话、下划线、打叉、括号 |
| 手写一句话 `Hand` | 霞鹜文楷或小赖字体，按字逐个用遮罩擦出 | 较长的手写句子（笔顺不重要的地方） |
| 笔迹 `Freehand` | `perfect-freehand` 由点列生成有粗细的笔迹，按进度截取点列 | 随手的涂鸦、连线、强调的“歪歪扭扭”线 |
| 计数 / 跳数 `Count` | 数字滚动，手写字体 | “第 7 次”“30 分钟” |
| 替换 `Swap` | 旧元素被划掉、淡出，新元素在原位画出 | “换个人、换份工作”，上面两层换了，底层不变 |
| 推镜 `Camera` | 世界画布加相机关键帧（平移和缩放） | 白板讲解的主镜头语言 |

- **出处**：Remotion 官方包（[evolvePath 文档](https://www.remotion.dev/docs/paths/evolve-path)）、[perfect-freehand](https://github.com/steveruizok/perfect-freehand)、[Hanzi Writer](https://github.com/chanind/hanzi-writer) 和 [hanzi-writer-data](https://github.com/chanind/hanzi-writer-data)、[rough-notation](https://github.com/rough-stuff/rough-notation)。

### ③ 一张大画布加相机，布局用“6×6 锚点网格”，已画的东西保留

- **大画布**：10 分钟的片子不能每 15 秒清一次屏。做法是每个段落在同一张“世界画布”上往外长：先画左边讲一部分，再平移到右边画下一部分，前面画的东西保留，最后拉远看全貌。这就是 hi-nikola 那个 skill 里说的“左右双语义岛”，也是白板讲解最有辨识度的地方。
- **6×6 锚点**：Code2Video（ICML 2026）把画布切成 6×6 的锚点，让 LLM 说“放在 B3”而不是写像素坐标；论文的消融实验里 6×6 最好，8×8 反而更乱。我们的 1920×1080 场景照做：每个元素声明占哪几个格子，渲染前自动检查有没有重叠、有没有压到字幕区。它还发现观众对“哪怕很短的遮挡”都很敏感，这正是我们第一版的毛病。
- **出处**：[Code2Video 论文](https://arxiv.org/html/2510.01174v1)、[hand-drawn-explainer-video-nikola](https://github.com/hi-nikola/hand-drawn-explainer-video-nikola)、[srt-whiteboard-animation](https://github.com/geeklee/srt-whiteboard-animation)（它的 `protectedRegions` 保护区，用来防止后画的东西提前露出来）。

### ④ 自动审片：印样、静止检测、独立审片 agent，分场景渲染

- **印样**：每秒抽一帧拼成网格，交给一个**没看过代码**的子 agent，它只拿到节拍表和印样，按“可读性、画面有没有在讲内容、音画是否同步、有没有遮挡”打分，并列出最差的三处。video-talkcraft 实测，把单帧改成 3×4 拼图后，评审从约 16 万 token 降到约 4 万。
- **机器检查**：ffmpeg 自带 `freezedetect` 滤镜，能找出“画面超过 N 秒没变化”的段落（参考片大约每 10–20 秒换一个视觉状态，我们设成超过 8 秒报警）。`blackdetect` 查黑帧。再加一条：遍历所有节拍，检查它锚定的那个字在字幕时间轴里确实存在。
- **分场景渲染**：每个段落注册成独立的 Composition，改一个镜头只重渲这一段。video-talkcraft 的数据是，改一个镜头出新片从整片重渲降到 53 秒。
- **审片轮数封顶**：机器检查全部通过后，只做 1 轮独立审片，修完 P0/P1 就交付，最多 3 轮（video-talkcraft 的规矩），避免无限循环烧 token。

### ⑤ 占位配音换成“你自己声音的克隆”，节奏按真实语速排

- 10 分钟的片子，画面节奏完全跟着旁白走。用 edge-tts 排的节奏，换成你的真录音以后会整体错位。用你的一段 30–60 秒干净录音，在本地克隆一个占位声音（Qwen3-TTS-1.7B-Base 或 Fun-CosyVoice3-0.5B，都是 Apache-2.0），排出来的节奏和最终成片接近。
- 本机已经有 GPT-SoVITS v2Pro，可以先用它，零安装成本。
- **规矩不变**：发布用真声。克隆声只用于内部预览，或补录一两个念错的字。只要用克隆声发布，就要按 AI 生成内容声明（见 §5.3）。

## 2. 参考片是怎么做出来的（推断）

### 2.1 能确认的事实

- B 站 [BV1GXav6iEWh](https://www.bilibili.com/video/BV1GXav6iEWh/)，UP 主“电子智人”，2026-09-28 上传，标签包括 claude、信息论、科普；标注“含 AI 生成内容”；3840×2160，时长 5:01（拆解见 `2_第二版资料/资料/参考片拆解_电子智人.md`）。简介只说是用 Opus 5.5 做的，**没有公开提示词、会话记录或源码**。B 站接口对我们的请求触发了风控（412），没能拿到更多元数据，所以没有继续抓。
- 同一时期 B 站有一批“Opus 5.5 短片”（[量子力学](https://www.bilibili.com/video/BV1a3av6eEuH/)、[AI 简史](https://www.bilibili.com/video/BV1H8av6HEYs/)、[群论之美](https://www.bilibili.com/video/BV12Zhm6oE6m/) 等），说明这是一波风潮，不是某个作者独有的技术。

### 2.2 Opus 5.5 “做视频”的公开做法

- Opus 5.5 **不直接生成视频**，所谓“视频输出”是写代码，由你的机器渲染（[OrcaRouter，2026-09-29](https://www.orcarouter.ai/blog/claude-opus-5-5-multimodal)）。
- 最常见的配方（[HF 博客](https://huggingface.co/blog/karmen-beatapi/how-to-make-videos-with-claude-opus-5-5)）：
  - 单个 HTML 文件，暴露 `window.DURATION` 和 `async window.seek(t)`；要求“每个像素都是 t 的纯函数，不用 Date.now、requestAnimationFrame、计时器、CSS 过渡、不带种子的 Math.random”。
  - 用 Playwright 驱动 Chromium，对每一帧调用 `seek(i/fps)` 再截图，通过管道送给 ffmpeg（H.264、yuv420p、CRF 18），第二遍再把音频混进去。
  - 提示词结构：时长、主题、受众、尺寸、禁止联网、seek 契约、配色字体运动风格、**只用核实过的事实**、音频（旁白逐词时间戳或 BPM）、**分阶段审批**（节拍表 → 关键帧 → 完整 HTML）。
  - 它列出的坑：模型偶尔会偷偷塞一个计时器进去；分给子 agent 做的章节接不严；讲解类内容会出事实错误，要提供核实过的资料；长时间渲染会中断，要先渲短区间。
- 一篇拆解病毒视频的文章（[explainx](https://explainx.ai/blog/claude-opus-5-5-western-civilization-video-2026)）说：每个场景是一个独立的 JS “画师”文件，无头 Chrome 大约 24 fps 截帧；所谓“一句话直出”**未经证实**，有第三方拆解认为其实分了两轮（先出分镜文档，再写代码）。

### 2.3 对参考片的推断

| 特征 | 最可能的做法（推断） | 我们的对应物 |
|---|---|---|
| 4K | Playwright 视口设成 3840×2160，或者 `deviceScaleFactor: 2` | Remotion `render --scale=2`：1920×1080 的合成直接输出 4K，矢量内容不会糊 |
| 暗底金色光点、辉光 | Canvas 2D，`globalCompositeOperation='lighter'` 加 `shadowBlur`，或者 WebGL 着色器；粒子位置用带种子的伪随机 | 我们是手绘风，不需要辉光。对应的“母题”是一种颜色的批注笔加一个贯穿全季的小人 |
| 每句话都有专门的演示 | **两轮生成**：先写分镜（每句旁白对应一个画面），再逐场景写代码 | §1 ① 的节拍表 |
| 旁白 | 片子标了“含 AI 生成内容”，旁白可能是 TTS，也可能只是因为画面是 AI 代码生成的，**无法确认** | 我们用真声 |
| 5 分钟没有穿帮 | 大概率分场景实现、分段渲染，最后拼接（HF 博客也提到“子 agent 的章节接不严”这个坑） | §1 ④ 的分场景渲染 |

**结论**：参考片能做到的，Remotion 都能做到，而且 Remotion 在确定性、预览（Studio）、分段渲染上更省心。要学的是它的**创作流程**（两轮生成加审批），不是它的渲染方式。

`beats.json` 的一个条目（示例）：

```json
{ "id": "S02-b04", "text": "你已经看了第七次手机",
  "anchor": "七", "occurrence": 1,
  "verb": "Count", "target": "phoneCounter", "args": { "from": 6, "to": 7 },
  "cells": ["E2", "F3"], "leadFrames": 6 }
```

- `anchor` 加上 `occurrence`：在字幕时间轴里找到这个字第几次出现的时间，动作提前 `leadFrames` 帧开始。画面稍微抢在声音前面，看起来更“同步”（经验值 4–8 帧）。
- `cells`：占用的锚点格。`qa_gates.py` 检查同一时刻有没有两个元素占同一格，有没有压到字幕区。
- 段落时长由音频决定，不手写帧数（和 claude-video-kit 一样，从真实 WAV 算）。

### 4.2 三个关键原语怎么实现（给写代码的 agent 看）

**描线（Draw）**：roughjs 的 `generator.toPaths(drawable)` 会给出多条路径（它的“双线”手绘感就来自这里）。把每条路径依次用 `evolvePath` 描出来，第二条比第一条晚 15%–25% 开始。时间按路径长度分配（`getLength`），这样长线画得久、短线画得快，看起来像真人在画。

**汉字逐笔（Write）**：Hanzi Writer 的做法是用 `medians`（中线）做遮罩。对每一笔，把它的中线画成一条很粗的描边路径，用 `evolvePath` 从 0 描到 1，再把这条描边当作 `<mask>`，去露出这一笔的轮廓 `strokes[i]`。一笔画完再画下一笔，笔与笔之间停 2–3 帧。数据坐标系是 1024×1024，y 轴朝上，需要 `scale(1,-1)` 翻转。每个字约 0.6–1.2 秒（经验值）。**注意**：这是楷体，和霞鹜文楷放在一起基本协调；和很潦草的手写字体放在一起会显得太工整。

**有粗细的笔迹（Freehand）**：先生成点列（可以从 roughjs 路径上用 `getPointAtLength` 采样），然后 `getStroke(points.slice(0, k), {size, thinning, smoothing, streamline, simulatePressure: true})`，其中 k 随进度增长。要求每帧结果一致，所以不能用真实的压感数据，只能用 `simulatePressure`；它按点的间距模拟压力，是确定性的。

### 4.4 下一步可以试：用 Excalidraw 当“画图入口”

- **为什么**：有些画面（小人姿势、手机界面、关系图）用代码一点点写坐标很慢，也不好看。Excalidraw 的画风和我们现在的 roughjs 线条是同一套算法，中文也有小赖字体。
- **怎么接**：你或者 agent 在 Excalidraw 里画好一张图，保存成 `.excalidraw`（就是 JSON：每个元素有类型、坐标、`seed`、`roughness`、`strokeWidth`）。我们写一个 `<ExcalidrawScene file order>` 组件：用同一个 `seed` 通过 roughjs 重新生成路径，再按 `beats.json` 里的顺序逐个元素描出来。这样“画出来的图”和“动画里的图”一模一样。
- **agent 能直接写这种 JSON**，Excalidraw 官方也有 mermaid 转 Excalidraw 的能力（本次没有核实具体包的状态，**未证实**）。
- **风险**：Excalidraw 的元素格式有版本差异，箭头绑定、文字换行要自己处理。先做一张图验证，再决定要不要推广。

### 4.5 以后再试：位图转逐笔笔迹

- [srt-whiteboard-animation](https://github.com/geeklee/srt-whiteboard-animation)（MIT）和 hi-nikola 那个 skill 走的是这条路：给一张线稿 PNG → 提取骨架或做网格扫描 → 生成连续笔迹 → 按区域、按字幕顺序落墨 → 先线稿后上色。
- **优点**：复杂插图（人物场景、有表情的小孩）也能“真的一笔一笔画出来”，这是纯 SVG 路线最难做到的。
- **缺点**：线稿从哪里来？用 AI 生图，就要做 AI 标识（第一版报告 §6.3）；你自己在平板上画，工作量大但完全原创。它输出的是 MP4，要作为视频层嵌进 Remotion（`<OffthreadVideo>`），不能和我们的相机、标注联动。
- **建议**：先不做。等“小人”这个母题需要更丰富的表情和动作时，再拿一两张你手画的线稿试。

### 5.3 克隆声音的合规要点（补充第一版 §6.3）

- 《人工智能生成合成内容标识办法》（2025-09-01 施行）第四条：合成人声这类内容，要在音频的开头、结尾或中间适当位置加语音提示或音频节奏提示，或者在界面上加显著提示（[网信办原文](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)）。这一条约束的是服务提供者；**作为发布者，你在抖音和 B 站都要主动勾选“含 AI 生成内容”**。
- 克隆的是**你自己的声音**，不涉及取得他人同意的问题。但注意：cs-board 这类工具里演示的名人或角色音色，一律不用。
- **建议的边界**：克隆声只用于①内部预览排节奏，②补录一两个念错的字（混在真声里、占比很小）。第二种情况从严理解也属于合成内容，最稳妥的做法是这期也勾选声明，或者直接重录那一句。

## 6. 排名推荐

### 6.1 现在就用（下一版就接进工程）

1. **节拍表加两道人工关卡**（§1 ①、§3.2）：不需要任何依赖，收益最大。
2. **`@remotion/paths`、`perfect-freehand`、`hanzi-writer-data`** 加上 roughjs 做原语库（§4.2）：全是 MIT 或 Arphic 许可，纯 JS 或 JSON，Windows 上没有安装风险。
3. **世界画布、相机、6×6 锚点和重叠检测**（§1 ③）：自己写，大约 300 行。
4. **QA 工具**：`qa_sheet.py`（ffmpeg `fps=1,tile=4x3`）、`qa_gates.py`（`freezedetect=n=0.003:d=8`、`blackdetect`、锚字检查、布局检查）、分段渲染，外加一个“只看印样的审片子 agent”。
5. **霞鹜文楷加小赖字体**：前者做标签和字幕，后者做随手批注。
6. **本地克隆占位声**：先用本机的 GPT-SoVITS，再试 Qwen3-TTS-1.7B-Base（单独建一个 Python 3.12 的 conda 环境，和 ASR 分开）。
7. 只装 Remotion 官方的 `remotion-best-practices` 一个 skill，放进项目的 `.claude/skills/`。

### 6.2 以后再试

- 用 **Excalidraw 当画图入口**，JSON 导入后逐元素描出（§4.4）。
- 从 **video-shotcraft**（Apache-2.0）挑两三种相机和转场，改成手绘风。
- **位图转逐笔**（srt-whiteboard-animation，§4.5），用你手画的线稿。
- **VoxCPM2**：换了更大显存的机器，或者它出了量化版以后再试。
- **@remotion/sfx**：笔划纸面、翻页之类的音效，每个音效要逐条确认许可。
- 用“**看完能答对题**”来评价一期（Code2Video 的 TeachQuiz 思路）：让一个没读过这本书的子 agent 只看印样和字幕，回答 3 道题，答不对说明讲得不清楚。这能直接检验你说的“把事情讲清楚”。

### 6.3 炒作，或者不适合我们

- **“一句话生成整条片子”**：没有人公开过完整会话；拆解文章本身也说是两轮以上（[explainx](https://explainx.ai/blog/claude-opus-5-5-western-civilization-video-2026)）。10 分钟的片子更不可能一句话出来。
- **换渲染器**（改用 HyperFrames、Motion Canvas、Revideo、纯 HTML 加 Playwright）：换了也补不上真正的差距，还要重写已有的东西。
- **直接照搬 video-talkcraft 或 anything2explainer 的代码**：非商用许可。思路可以学，代码不能用。
- **vivus、rough-notation、hanzi-writer 的播放器**：都靠计时器或 CSS 动画，在 Remotion 里会闪烁或者无法复现，只能借它们的数据和算法。
- **Code2Video、TheoremExplainAgent、Manim 系工具**：做数学和理工科公式动画的，心理书用不到；学它们的方法论就够了。
- **AI 视频生成模型**（MiniMax H3 之类）：画面不可控，没法做到“每句话一个精确演示”，还要做 AI 标识。
- **星数和“安装量”**：skill 目录里 180 多个仓库，多数是英文竖屏带货模板；非交互安装会一次装上全部 skill，所以安装量有水分（第一版已指出）。本次看到星数最高的几个中文手绘 skill，也大多依赖 AI 生图。
- **声音克隆里的 F5-TTS、Spark-TTS、Fish S2、MegaTTS3**：见 §5.1，许可或功能上不适用。

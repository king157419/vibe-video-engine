# 萤火 firefly：vibe知识大赏 短片怎么做

> 名字取自「囊萤夜读」。本文件是总纲，细节在 `references\` 下：
> - `规则清单.md`：全部规则，新旧矛盾以谁为准（§7），两张出厂检查表（§8），还没定的事（§9）
> - `制作命令.md`：命令、文件格式、门槛、坑
> - `模板.md`：所有文档模板，加交付清单
> - `改片流程.md`：定位问题，改片 Workflow，中断后续跑
> - `scripts\`：第四版实际跑过的三个 Workflow 脚本，当 prompt 骨架用：`v4-scripts-wf.js`（写剧本 → 三位审稿 → 修改）、`v4-build-wf.js`（制作 → 两位审片 → 修）、`v4-revise-1012-wf.js`（10-12 改片实例）

## 这是什么

- **类型**：抖音 #vibe知识大赏，4–5 分钟横屏短片。
  - 画面全部用代码画（Remotion v4，`video-engine\src\v4`），近黑底，光是主角。
  - 中英双语衬线字幕，没有旁白。
  - 配乐用我们自己的 Python 合成（`video-engine\tools\score.py`）。
- **每部片**讲一个有名字的大想法（学名 · 人名 · 年份）：
  - 开场是此刻发生在观众身上的一件事。
  - 片名卡等这段体验过去才出。
  - 反转处放一个满屏奇观，紧接一段硬静音。
  - 结尾回到开头。
  - 参考片：电子智人《信息论》（BV1GXav6iEWh），本地在 `3_第三版资料\参考视频\BV1GXav6iEWh.mp4`。
- **最新状态**：看根目录 `README.md` 的版本表和 `references\规则清单.md` §9；做完一件就在那里划掉。

## 用户是谁，怎么跟用户说话

- 说中文，不写代码，时间少，最怕来回返工。
- 回复用白话，要短，不自夸。顺序：东西在哪（完整路径）→ 改了什么（附新片里的时间点）→ 只有用户能定的事（编号）。
- 「只有用户能定的事」只放内容和口味上的选择。代码怎么放、用什么工具这类事，自己定，不问用户。
- Claude 听不到声音，所以凡是涉及声音的地方，都要写清「几分几秒，听什么」。

## 守住的几条，和为什么

1. **先讨论，再动手。**
   - 成片做完再让用户挑毛病，返工成本全落在用户身上。
   - 用户的原话：「先抛出一个主题，我们讨论一下……而不是直接成片出来我再去挑问题改，这样沟通和修改的成本实在太大了」。
2. **参考片就是规格。**
   - 第三版只照文字清单做，结果被评「看不出来一点相似」。
   - 所以每部片都要和《信息论》并排比印样。
3. **中文台词由 Kimi 写，比较一律盲比。**
   - 用户一眼看出「kimi 写的更像是人在说话」，Opus 的中文有时读着像翻译。
   - Claude 不能「自己当运动员又当裁判」。
4. **每部片配一句文化引用，适用范围要和概念一样大。**
   - 引用负责「升华」，《锦瑟》和《故乡》都被用户夸过。
   - 费孝通「差序格局」讲的是中国社会，而弱关系是普遍现象，所以被否。
   - 用之前逐字对原文。
5. **讲透，不造词，数字靠对比。**
   - 先讲机制，再举例子。第三版的「倒时差」只报了名字，没讲清楚，失败了。
   - 「室温时间」这种自造词让人看不懂。
   - 刷短视频的人记不住前面出现过的数，所以要写「只暖了1度」。
6. **声音要老实。**
   - 每一声叮都要落在画面上一个看得见的重点。
   - 震撼那一拍之后的硬静音要留够反应时间，一般 2–3 秒；像《峰终》「戛然而止」那样的一拍用满 3 秒（用户：「我都没反应过来就继续了」）。
   - 硬静音那一帧，画面也要有明显动作：切到或淡到近黑，或者主角定住、尘埃照飘。不然会被当成卡顿，《弱关系》2:56 和《赫布》3:08 就被报成「卡了一下」。
   - 不用铅笔或手写的沙沙声，不放连续刺耳的不协和段落。
7. **署名只写 Opus 5.5。**
   - 片尾最后 2 秒只有一行极小的「Opus 5.5」。
   - 简介末句是「画面、配乐与双语字幕全部由 Opus 5.5 用代码生成」。
   - 发布时勾选「含 AI 生成内容」。
8. **新一批先做一部样片。**
   - 用户叫停过一次批量生成。
   - 先交一部样片和后续规划，用户认可后再扩。

## 流程

每一步都写了：目标、Claude 做什么、在哪儿停下来等用户、产出放哪。标了「停」的地方一定要停，不替用户做决定。

### 0. 复盘（不挡选题）
- 有已发布、还没复盘的片子（见 `规则清单.md` §9）时，手上的事照常做（比如照常出提案），在那条回复末尾顺带要数据：完播率、平均播放时长、在哪儿掉人（几分几秒）、评论原文或截图。
- 数据来了再单独复盘：对着片子的时间轴，查掉人那一刻屏幕上和字幕里是什么，写成三到五条结论，给用户看，问用户是否同意。
- **放哪**：被复盘那部片所在版本的资料夹，例如 `4_第四版资料\复盘_峰终_MMDD.md`。复盘完在 §9 划掉。

### 1. 选题提案（停，讨论）
- **目标**：让人有兴趣。贴季节和天气，或者贴热点。
- **找热点**：
  - 用现成工具，例如 WebSearch 搜公开热榜，或者会话里接着的趋势工具。不自己写爬虫。
  - 不绕过 B 站的 412 风控，不登录，不用 cookie，不改代理。
  - B 站公开 API 只用 WebFetch 访问。抖音网页打不开。
  - 要把别人视频的口播转成文字，用 BibiGPT 这类网页工具，不在本地跑脚本。
- **先看现成的候选**：`4_第四版资料\片单.md` 的「候选池」、`规则清单.md` T11、`5_第五版资料\文案对比\甲.md` 和 `乙.md` 的「一、三个选题」（按上海入秋写的）。从里面挑或改，再补新题。
- **查重**：对照 `4_第四版资料\片单.md` 末尾的「账本」，发布过的知识点不重复。第三版的旧题（刹车、剩饭、熬夜）没发布过，可以重做，但提案里要说明是重做、这次哪里不一样。
- **提案**：由 Opus 按 `references\模板.md` §1 的表写，抛 2–4 个选题，每个写清：
  - 钩子
  - 醍醐灌顶的那一下
  - 开头 10 秒观众身上发生什么
  - 有名字的大想法（学名 · 人名 · 年份）
  - 文化引用，以及它的适用范围
  - 为什么是这几天
- Kimi 任务书里的选题节，只在用户要比稿时用。
- **停**：把提案发给用户讨论。方向没定之前，不写剧本，不写代码。
- **放哪**：`<n>_第<n>版资料\选题提案_MMDD.md`。讨论结论补在同一文件末尾的「讨论结论」。

### 1b. 用户直接点名一个题时（停，确认一次）
- 讨论不能省，但只发一页：用 `模板.md` §1 的表，把这个题的开头 10 秒、醍醐灌顶的那一下、文化引用（原文 + 出处 + 为什么够普遍）和落点写出来，请用户确认。
- 结论写进 `选题提案_MMDD.md` 的「讨论结论」。不写这一条，剧本阶段检查表的第一道闸过不去。
- 已经有底稿的，就在底稿上改，不从零重写。例子是**风寒效应**（slug `windchill`）：
  - 底稿是 `5_第五版资料\文案对比\谜底_比完再开\raw_kimi.md`，也就是甲里的完整文案《偷热的风》。用户评过「kimi 写的更像人在说话」。
  - 它是照旧任务书写的，没有引用，也没有约 3 秒的停顿、冒号和破折号这几条新规矩。
  - 所以先由 Opus 按第 2 步补骨架，再写一份中文任务书，把要补引用、停顿和标点的地方发回 Kimi 改。

### 2. 定结构（Opus 做，写到节拍这一级）
- **目标**：把讨论定下的思路变成一条概念阶梯。
- **骨架要有**：
  - 5–7 章，每章教一级，下一章要用到。
  - 每个节拍：一个画面主角、大致秒数、要讲清的那件事。
  - 开场体验；片名卡位置（约 15–35 秒）；升尺度。
  - 反转、满屏奇观、硬静音（2–3 秒，写明画面同步做什么）。
  - 引用那一章；落点句；首尾回环。
  - 每一声叮放在哪个节拍，对应哪个画面重点。
- 这一步不写逐句台词，逐句台词是第 3 步 Kimi 的活。
- 规则全集见 `references\规则清单.md`。
- **放哪**：`<n>_第<n>版资料\<slug>\剧本.md`，模板见 `references\模板.md` §3。slug 用一个英文小写词。

### 3. 中文台词交给 Kimi
- **写任务书**：用中文写，照 `references\模板.md` §2。讨论结论填进「讨论定的思路」，第 2 步的骨架贴进「剧本骨架」。
- **调用**：
  ```
  D:\conda\envs\d2l\python.exe video-engine\tools\kimi.py --prompt <任务书.md> --out <raw_kimi.md> --model k3 --effort max
  ```
  - key 在 `D:\desk\claudex\24\.env` 的 `KIMI_API_KEY`，不要打印出来。
  - 返回 401，说明用户的套餐不含这个模型：先换 `--model k3-256k` 再试；还不行就停下告诉用户。不改用 Opus 写中文。
- **Kimi 交稿之后**（Opus 做）：
  - 对齐骨架。每一句配画面栏：一个主角；独立元素 ≤6 个；多数帧 ≤8 个汉字。
  - 每一声叮对上画面上的重点。
  - 核事实，翻英文字幕。
  - 保留 Kimi 的说话味道。要改的句子用中文写清楚发回给 Kimi 改，Opus 不自己定稿中文。
- **盲比**（比较模型或两版文案时）：
  - 两份稿改名为 `甲.md` 和 `乙.md`，开头只写一样的说明。
  - 谜底放进单独的文件夹 `谜底_比完再开\`。
  - Claude 不打分，由用户或独立评审来判。有盲比就等用户判完再往下。
  - 样例在 `5_第五版资料\文案对比\`，其中 `任务书.md` 可以直接当任务书的范本。
- **放哪**：定稿台词写进 `<slug>\剧本.md`。Kimi 的原稿和 reasoning 文件留在资料夹里。

### 4. 事实核查，引用逐字核对
- 每个人名、年份、实验数字、引用原文都写进 `事实核查.md`，附出处和网页原句。
- 查不到的就删掉或换个说法。示意性的数字在画面上标「示意」。
- 引用要找到原文逐字对。例如「君子之交淡若水」出自《庄子·山木》，常见误写成「淡如水」。
- **放哪**：`<slug>\事实核查.md`，模板见 `references\模板.md` §4。

### 5. 三位审稿人
- 照 `references\scripts\v4-scripts-wf.js` 里 `REVIEWERS` 的三段 prompt，起三个互相独立、没参与写稿的 agent（用 Workflow 或 Agent 子代理都行）。脚本里的旧路径要换成现在的，头注里写了对照。
  - **genre**：像不像这个类型。
  - **facts**：对抗式事实核查。
  - **user**：站在用户的角度看。
- P0、P1 级意见全部改。要改中文台词的，照第 3 步发回 Kimi。
- **放哪**：`<slug>\审稿记录.md`，模板见 `references\模板.md` §5。

### 停：剧本给用户过目（3–5 都做完再停）
- 发一页给用户，只列这三样，再附上全片台词的路径：
  1. **引用**：原文、出处，以及为什么够普遍。
  2. **开头 10 秒**：观众身上发生什么，屏幕上是什么。
  3. **醍醐灌顶的那一下**：在几分几秒，屏幕上是什么。
- 用户认可了才进第 6 步。之后如果改到用户看过的台词、引用或开场，把改前和改后对照着再发给用户确认。

### 6. 制作
- **目录**：
  - 代码：`video-engine\src\v4\<slug>\`
  - 数据：`video-engine\public\v4\<slug>\`
  - 草稿：`video-engine\out\v4\<slug>\`
  - 资料：`<n>_第<n>版资料\<slug>\`
- **边界**：只改自己的目录。`src\v4\kit` 只读，要改就把组件复制到片子目录里改。
- **第五版也沿用 `src\v4\<slug>` 和 kit**：外壳不变就是系列感。这件事不问用户，只有外观要变时才问。
- **顺序**：
  0. 开新片：按 `references\制作命令.md` §6 建四个目录；抄 `4_第四版资料\hebb\tools\subs_timeline.py`、`4_第四版资料\peak\mix.py` 和 `video-engine\src\v4\ties\fontReady.ts`；写 `index.ts`、`Root.tsx`、`data.ts`；Composition 叫 `V4<Slug>`（例如 `V4Windchill`）。
  1. 用一个生成脚本算出 subs.json 和 cue.json，不手改 json。
  2. score.py 合成 music.wav。
  3. mix.py 做两遍 loudnorm，得到 mix.wav。
  4. tsc 类型检查。
  5. 出关键帧静帧。
  6. 出半尺寸草稿，跑 v4_qa。
  7. 全尺寸渲染。TEMP 指到 D 盘，`--concurrency=5`。
  8. 用 mix.wav 重新封装音轨。
  9. 自检。
- 用 agent 做时，prompt 骨架是 `references\scripts\v4-build-wf.js`：一个 agent 制作，两位独立审片，再修一轮。头注里写了哪些地方已经过时。
- 全部命令、文件格式和门槛见 `references\制作命令.md`。

### 7. 自检，再加独立核查
- **自检项目**：
  - v4_qa：平均亮度 8–15，细节密度 ≤4%，没有 8 秒以上的静止，和参考片并排比。
  - v4_stutter：FREEZE 为 0，每个 POP 都写清是有意的。
  - ebur128：−16 LUFS，TP ≤ −1.5，LRA 7–10。
  - 改动处和每一声叮的位置都抽全尺寸帧，一张张看。
- 结果追加进 `<slug>\自检记录.md`。
- **独立核查**：另起一个没参与制作的 agent，自己打开片子、自己跑工具、自己看帧，给出过或不过。
- 两张出厂检查表见 `references\规则清单.md` §8。

### 8. 交付（停，等用户看）
- 成片只放在 `D:\desk\claudex\24\成片\<n>_第<n>版_<说明>\`，里面有：
  - `<字母>_<片名>.mp4`
  - `<字母>_<片名>_封面.png`（片名卡那一帧）
  - `<字母>_<片名>_发布文案.md`
  - `手机预览\<字母>_<片名>_手机预览.mp4`（1280×720，约 25 MB）
  - `交付说明.md`
- 同时更新 `成片\成片目录.md` 和根目录的 `README.md`，在 `4_第四版资料\片单.md` 的「账本」登记一行。
- `video-engine\out\` 只放草稿，不要让用户去那里找东西。
- 手机预览用 SendUserFile 发给用户，用户可能在手机上看。
- 命令见 `references\制作命令.md` §9，模板见 `references\模板.md` §6–§9。

### 9. 改片
- **用户报了一个时间点**（比如「3:00 好像卡了一下」）：先按 `改片流程.md` §0 定位，确认真有问题再动手。
- 先把用户的意见分成两类（细则见 `改片流程.md` §1）：
  - **明确的**：改什么、改成什么都清楚。直接改。
  - **模糊的，或关于整体观感的**：先讨论，不动手。只说「这句换个说法」、没给新词的也算这一类：用 Kimi 出 2–3 个候选，让用户挑。
- **明确的意见这样改**：
  0. 先加载 workflow-authoring skill。只有一部片、改动很小，或者没有 Workflow 工具时，不起 Workflow，改用两个 Agent 子代理：一个修改，一个独立核查，prompt 照 `改片流程.md` §4 的 `fixPrompt` / `verifyPrompt`。
  1. 起一个 Workflow，每部片一个修改 agent。
  2. 每部片再配一个独立核查 agent。
  3. 没通过就再修一轮。
  4. 负责人收尾：抽查，把旧版移进 `旧版_MMDD\`，出手机预览，同步文档，发给用户。
- **片子已经发布了**：抖音已发的视频一般不能换文件（以平台当时的规则为准）。回复里先说明新版用在哪：B 站、重发，还是只留作底版。
- **中途被用量或会话限制打断**：找出开工后改过的文件，在提示里加 RESUME 说明后重跑。从当前状态接着做，不从头来，也不盲目回退。
- 全流程和可复用的脚本见 `references\改片流程.md`。

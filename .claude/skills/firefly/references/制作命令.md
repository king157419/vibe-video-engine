## 2. 标准命令顺序（PowerShell）

占位符：`<slug>`（如 `peak`）、`<Comp>`（如 `V4Peak`）、`$DOC`（这部片的资料目录）。

```powershell
# --- 0. 环境（CONTRACT §4）---
$py  = 'D:\conda\envs\d2l\python.exe'
$VE  = 'D:\desk\claudex\24\video-engine'
$DOC = 'D:\desk\claudex\24\4_第四版资料\<slug>'      # 第五版改成 5_第五版资料\<slug>
$env:TEMP="D:\tmp\v4<slug>"; $env:TMP=$env:TEMP; New-Item -ItemType Directory -Force $env:TEMP | Out-Null
Set-Location $VE          # 下面所有相对路径（tools\、public\、src\、out\）都相对于 VE

# --- 1. 锁定剧本 -> subs.json / cue.json / meta ---
# 只用一个生成脚本产出这几个文件。不要手改 json
& $py "$DOC\tools\subs_timeline.py" --out "$VE\public\v4\<slug>"   # 赫布式：写出 subs.json、cue.json、timeline_meta.json；违反规则时以 1 退出
#   峰终式：& $py "$DOC\build_timeline.py" --write            # 写出 subs/cue/numbers.json，输出路径写死在脚本的 OUT_PUB 里
#   弱关系式：& $py "$DOC\ties_timeline.py" write ; node src\v4\ties\gen_data.mjs   # 第二步把 json 烘进 src\v4\ties\data.gen.ts

# --- 2. 配乐 ---
& $py tools\score.py public\v4\<slug>\cue.json public\v4\<slug>\music.wav
#   赫布换用了更柔和的钟声：& $py "$DOC\tools\score_hebb.py" public\v4\hebb\cue.json public\v4\hebb\music.wav

# --- 3. 混音：EQ（+ 限幅）+ 两遍 loudnorm + 把静音段强制清零（峰终的 mix.py 最通用）---
& $py "$DOC\mix.py" public\v4\<slug>\music.wav public\v4\<slug>\mix.wav `
  "equalizer=f=95:t=q:w=1:g=-3,equalizer=f=190:t=q:w=1:g=-1.5,alimiter=limit=0.5:attack=4:release=60:level=disabled" `
  public\v4\<slug>\cue.json
#   看第二遍打印出的 JSON：normalization_type 必须是 "linear"

# --- 4. 类型检查（记录里的结果是「0 错误」）---
node node_modules/typescript/bin/tsc --noEmit -p .

# --- 5. 静帧（单帧；每次调用都会重新打包，比较慢）---
node_modules\.bin\remotion.cmd still src\v4\<slug>\index.ts <Comp> out\v4\<slug>\st1\f_900.png --frame=900
#   批量出帧（只打包一次、只开一个浏览器）：优先复制 VE\src\v4\hebb\tools\stills.mjs（没有写死打包目录）
#   参数是 <outDir> <scale> <frame...>，把文件里的 entryPoint 和 id 改成自己的，在 VE 目录下运行
#   如果抄的是 VE\out\v4\peak\stills.mjs：它还写死了 bundle 的 outDir: 'D:/tmp/v4peak/stillbundle'，要改成 D:/tmp/v4<slug>/stillbundle，否则几部片并行时会互相覆盖

# --- 6. 半尺寸草稿 + 自检（CONTRACT §4）---
node_modules\.bin\remotion.cmd render src\v4\<slug>\index.ts <Comp> out\v4\<slug>\draft.mp4 --scale=0.5 --concurrency=6
& $py tools\v4_qa.py out\v4\<slug>\draft.mp4 out\v4\<slug>\qa_d1

# --- 7. 全尺寸渲染（峰终约 9 分钟，赫布 9.5 分钟，都是 concurrency 5，约 8.7k 帧）---
node_modules\.bin\remotion.cmd render src\v4\<slug>\index.ts <Comp> out\v4\<slug>\final_render.mp4 --concurrency=5

# --- 8. 用 mix.wav 重新封装音轨（去掉 Remotion AAC 带来的 42.7 ms 延迟；峰终 10-12 的做法）---
ffmpeg -y -i out\v4\<slug>\final_render.mp4 -i public\v4\<slug>\mix.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 320k -ar 48000 -movflags +faststart out\v4\<slug>\final.mp4
#   不要加 -shortest（峰终的记录：「加了会被 AAC 的边界截掉最后 3 帧」）

# --- 9. 检查 ---
ffprobe -v error -show_entries stream=codec_name,width,height,nb_frames,bit_rate,color_space,color_range -show_entries format=duration -of compact out\v4\<slug>\final.mp4
& $py tools\v4_qa.py out\v4\<slug>\final.mp4 out\v4\<slug>\qa_final
& $py tools\v4_stutter.py out\v4\<slug>\final.mp4 | Out-File -Encoding utf8 out\v4\<slug>\stutter_final.txt
ffmpeg -hide_banner -nostats -i out\v4\<slug>\final.mp4 -af ebur128=peak=true -f null -          # 看 "Summary:" 里的 I / LRA / Peak
ffmpeg -hide_banner -nostats -i out\v4\<slug>\final.mp4 -af silencedetect=n=-60dB:d=0.4 -f null - # 只应该出现计划中的那段硬静音

# --- 10. 清理（CONTRACT：「渲染完删掉 D:\tmp\v4<slug> 里的 remotion-webpack-bundle-*」）---
Remove-Item -Recurse -Force "D:\tmp\v4<slug>\remotion-webpack-bundle-*"
Remove-Item out\v4\<slug>\final_render.mp4
#   v4_qa.py 会在 D:\tmp\v4qa_* 留下抽帧目录（现在已经有 40 多个），也一起删
```

**改片前**：先把旧的 `out\v4\<slug>\final.mp4` 改名为 `final_<MMDD>.mp4`，MMDD 是用户看过的那一版的日期，例如 `final_1008.mp4`；同名文件已经存在就不要覆盖。峰终还额外把源码备份到了 `out\v4\peak\bak_1008\`。

## 3. 三部片在 10-12 实际是怎么跑的

**峰终**（`4_第四版资料\peak\自检记录.md`「3. 出片（可复现）」）：
```
D:\conda\envs\d2l\python.exe 4_第四版资料\peak\build_timeline.py --write
D:\conda\envs\d2l\python.exe tools\score.py public\v4\peak\cue.json public\v4\peak\music.wav
D:\conda\envs\d2l\python.exe 4_第四版资料\peak\mix.py public\v4\peak\music.wav public\v4\peak\mix.wav "equalizer=f=95:t=q:w=1:g=-3,equalizer=f=190:t=q:w=1:g=-1.5,alimiter=limit=0.5:attack=4:release=60:level=disabled" public\v4\peak\cue.json
node node_modules/typescript/bin/tsc --noEmit -p .        → 0 错误
remotion render src\v4\peak\index.ts V4Peak out\v4\peak\final_render.mp4 --concurrency=5   （TEMP=D:\tmp\v4peak，约 9 分钟）
ffmpeg -i final_render.mp4 -i mix.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 320k -ar 48000 -movflags +faststart final.mp4
```
- 第一行相对于 `D:\desk\claudex\24`，其余几行相对于 VE。
- 混音第二遍的结果：I −16.04、TP −2.00、LRA 7.7，linear。成片是 I −16.1 LUFS、LRA 7.7 LU、真峰值 −1.8 dBTP，共 8742 帧。
- 成片音轨和 mix.wav 做互相关，滞后 0 个样本。

**赫布**（`hebb\自检记录.md` 2026-10-12 一节的开头）：
`subs_timeline.py --out public\v4\hebb` → `score_hebb.py cue.json music.wav` → `mix.py music.wav mix.wav`（EQ + 两遍 loudnorm，第二遍 LRA 10）→ `tsc --noEmit`（0 错）→ `remotion render src\v4\hebb\index.ts V4Hebb out\v4\hebb\final.mp4 --concurrency=5 --audio-bitrate=320k`
- 没有重新封装音轨，所以 42.7 ms 的偏移还在。
- 渲染前先查了可复现性：重新生成的 json 和磁盘上的逐字节相同，重新合成的 wav MD5 也相同。

**弱关系**（`ties\自检记录.md` 10-12 一节的 §5）：
```
ties_timeline.py write
node src/v4/ties/gen_data.mjs
tools/score.py public/v4/ties/cue.json public/v4/ties/music.wav
out/v4/ties/tools/mix.py 0.32
```
- 记录里没写渲染命令。【推断】是 `remotion render src\v4\ties\index.ts V4Ties out\v4\ties\final.mp4 --concurrency=5 --jpeg-quality=95 --audio-bitrate=320k`。依据：记录写了「crf 18（jpeg 95）」，而配置文件默认是 92。
- 同样没有重新封装，42.7 ms 的延迟还在。

## 5. 文件格式

### 5.1 `public\v4\<slug>\subs.json`：全片的时钟

一个 `{t0, t1, zh, en}` 列表，单位是播放时间（秒）。kit 里的类型是 `Sub = {t0; t1; zh; en?}`（`kit\theme.ts`）。
```json
[{"t0": 6.4, "t1": 11.4, "zh": "你已经听出来，它要落在哪儿。", "en": "You can already hear where it wants to land."}, ...]
```

生成脚本会检查这些规则（CONTRACT §0.5、§2）：

| 规则 | 值 |
|---|---|
| 在屏时间 | ≥ 中文字数/4 + 1.5 秒，并且在 4–8 秒之间 |
| 句间空隙 | 0.6–1.2 秒 |
| 提问之后 | 留 2–8 秒空白（赫布） |
| 更长的空隙 | 必须写理由（赫布用 `beat(d, note)`，峰终用 `EXEMPT`） |
| 句长 | 平均 12–20 字；赫布的检查是 ≤22 |
| 禁用词 | `['答案','记住','注意','建议','先选','错在','留个题','作业','正确','知识点','应该','记得','别']` |

三个生成脚本数字数的方法不一样：峰终每个汉字算 1、一串数字算 1；弱关系算汉字加每个数字或字母；赫布算汉字加每个字母数字。

### 5.2 `cue.json`：给 `tools\score.py` 的输入

时间单位都是秒。输出是 48 kHz、16-bit 立体声 wav。

**顶层**

| 字段 | 默认值 | 说明 |
|---|---|---|
| `dur` | 必填 | Root 也用它决定片长 |
| `key` | `"D"` | C、C#、Db … B |
| `mode` | `"minor"` | `major` / `minor` / `dorian` / `lydian` |
| `bpm` | 70 | |
| `seed` | 7 | |
| `rt60` | 3.6 | 长混响 |
| `ramp` | 1.5 | 段落之间强度过渡的汉宁平滑时长（秒） |
| `fade_in` / `fade_out` | 1.0 / 4.0 | |
| `motif` | `[[0,1],[2,1],[4,2]]` | `[音级或 null（休止）, 拍数]` 的列表；音级 7 = 高八度 |
| `sections` | 必填 | 必须按 t0 排序。音量曲线从每段的 t0 用到下一段的 t0 |
| `hits` | `[]` | 点位音效 |
| `silences` | `[]` | `[[a,b],…]` 硬静音 |

**sections 里的每一段**

| 字段 | 默认值 | 说明 |
|---|---|---|
| `t0`, `t1` | 必填 | |
| `chords` | `["i"]` | 罗马数字和弦。大写是大三度，小写是小三度；前缀 `b` 表示降；后缀可以是 `add9`、`sus2`、`sus4`、`maj7`、`7`、`9` |
| `bars_per_chord` | 2 | |
| `layers` | — | `{piano, pad, low, pulse}`，各乐器的增益，不写或写 0 就是关掉。`pulse` 是每拍一下的心跳声 |
| `piano` | `"sparse"` | `sparse`（按 `density` 随机，默认 0.5）、`arp`/`arp8`（八分音符）、`arp16`、`chordal`、`motif`（奏本段或全局的 motif，加左手根音） |
| `register` | 0 | 八度偏移 |
| `velocity` | 0.55 | |
| `motif` | — | 覆盖全局 motif |
| `pad_attack` | 1.8 秒 | |
| `pad_bright` | 0.35 | |
| `intensity` | 0.7 | 这一段的总增益，**钟声也一起被它放大** |

多写的键会被忽略，可以拿来写注释：例如赫布的 `name`、弱关系的 `_why`、赫布 hit 里的 `note`。

**hits**：`{type, t, gain=1, pan=0.5, …}`

| type | 音高 / 长度 | 说明 |
|---|---|---|
| `bell` | MIDI `48+key_pc+36+SCALE[mode][deg]`，deg 默认 0 | E 小调 deg 4 = B6（1976 Hz）；A dorian deg 0 = A6（1760 Hz）；F lydian deg 4 = C7 |
| `ding` | 比 bell 高一个八度（`+48`），deg 默认 4 | 审稿时被嫌太尖，三部片都换成了 `bell` |
| `boom` | `len` = 5.0 | 片名处的重击 |
| `riser` | `len` = 3.0 | **`t` 是结束时间**，从 t − len 开始响 |
| `sour` | `len` = 0.9，`semi` = 0 | 往下塌的音团 |
| `note` | 必须给 `midi`，`len` = 2.0 | 一个钢琴音，不算点位音效 |

**silences**
- 从 a 到 b 音乐被硬清零，之前有 12 ms 的淡出，之后有 0.25 秒的淡入。音效的混响尾巴在之后 3 秒内也被掐掉。
- 母带处理随后会加 28 Hz 高通、tanh 软削波，峰值压到 −3 dBFS。**这个高通会往静音段里拖大约 50 ms 的余振**，所以混音时要把静音段再清零一次（见峰终 `mix.py` 的说明文字）。

**三部片现在的实际值**

| 片 | 顶层 | 段数 | hits | 硬静音 |
|---|---|---|---|---|
| 峰终 | E minor，64 bpm，seed 11，rt60 3.8，fade 0.3 / 1.5，dur 291.4 | 29 | bell 7、boom 2、note 4、riser 1 | [193.15, 196.15] |
| 弱关系 | F lydian，72 bpm，seed 1973，rt60 4.2，fade 0.3 / 4.0，dur 285.2 | 18 | bell 8、boom 3、riser 1、note 15 | [176.37, 177.87] |
| 赫布 | A dorian，64 bpm，seed 49，rt60 4.0，ramp 1.2，fade 0.05 / 2.5，dur 287.8 | 20 | bell 10、boom 2、riser 2、note 6 | [188.6, 190.1] |

（这些是调研时的数值。10-12 改片后，峰终和赫布的时长、hits 可能已经变了，以磁盘上的文件为准。）

### 5.3 meta / numbers 文件（每部片不一样）

- **峰终 `numbers.json`**：由 `build_timeline.py --write` 写出。`film_curve` 用的是和 score.py 音量曲线相同的算法（`intensity_curve()`），所以片子画的就是它自己配乐的响度曲线。`Root.tsx` 在运行时用 `calculateMetadata` + `fetch(staticFile('v4/peak/numbers.json'))` 读取。
- **赫布 `timeline_meta.json`**：由 `subs_timeline.py --out` 写出。里面的 `time_map` 是 `[[场景时间, 播放时间], …]`，subs.json 和 cue.json 已经映射成播放时间；`numbers.dings_total` 会和 deg-0 钟声的个数做交叉核对。
- **弱关系**：`ties_anchors.json`（每次运行都重写的真实时间锚点）、`ties_anchors_story.json`（冻结的 v2「故事时间」锚点）、`ties_numbers.json`（Watts–Strogatz 模型，N 2000、K 20、p 0.01、mulberry32）。`node src\v4\ties\gen_data.mjs` 把它们烘进 `src\v4\ties\data.gen.ts`。

**共同的做法是两套时钟。** 字幕、cue、章节标签、片尾署名和音频都走真实的播放时间；画面代码走一套冻结的场景时间，两者之间用分段线性映射换算。三部片的实现分别是：峰终 `warp.ts`（`toOld`/`toReal`），弱关系 `time.ts`（`story`/`real`），赫布 `data.ts`（`toScene`/`toPlay`）。这样改片时字幕变长变短，不必重写动画里的时间戳。新片从恒等映射开始。

## 6. 开一部新片（slug）

**规矩**（CONTRACT §0.1）：只改自己的目录：`src/v4/<slug>/**`、`public/v4/<slug>/**`、`<版本>资料/<slug>/**`、`out/v4/<slug>/**`。不要改 `src/v3/**`、`src/Root.tsx`、`package.json`，不要 `npm install`。kit（`src/v4/kit/**`）对每部片都是只读的，需要改的组件复制到自己的目录里再改。峰终的 `Subs.tsx` 就是这样复制出来的，加了 `hardOut`，让字幕和硬切在同一帧消失。

**目录结构**
```
VE\src\v4\<slug>\index.ts, Root.tsx, Video.tsx, data.ts, Overlay.tsx, scenes\*.ts, (lib\…)
VE\public\v4\<slug>\subs.json, cue.json, [timeline_meta.json|numbers.json], music.wav, mix.wav
$DOC\剧本.md, 事实核查.md, 审稿记录.md, 自检记录.md, 发布文案.md, <生成脚本>.py, mix.py
VE\out\v4\<slug>\  (draft.mp4, st*/, qa_*/, final.mp4, stutter_*.txt)
```

**`index.ts`**

## 7. 自检项目和门槛

**A. 生成脚本自检（在做任何声音之前）**：在屏时间 ≥ 字数/4 + 1.5 并在 4–8 秒之间；句间空隙 0.6–1.2；提问后停 2–8 秒；禁用词；点位音效（`bell` / `ding` / `boom` / `riser`）每片 ≤15 个（CONTRACT §0.6）；deg-0 钟声逐一计数（赫布）。峰终脚本打印 `PROBLEMS: none`，赫布脚本有错就以 1 退出。

**B. `tools\v4_qa.py <video> <outdir>`**
- 产出 `sheet_XX.jpg`（每 5 秒一帧，6 列，每张 30 帧）、`vs_reference.jpg`（本片对《信息论》`3_第三版资料\参考视频\BV1GXav6iEWh.mp4`，每 10 秒一帧，取前 3 分钟）和 `metrics.json`。临时帧放在 `D:\tmp\v4qa_*`，所以 `D:\tmp` 必须存在。
- **亮度**：每 5 秒取一帧 480×270 求平均灰度。脚本里写的通过线 `pass_lum: mean ≤ 41` 已经过时，以 CONTRACT 为准：平均 8–15，背景 ≤12。实际结果：峰终 10.3，弱关系 10.0，赫布 11.9。
- **细节密度**：|dx| + |dy| > 48 的像素占比，平均 ≤4.0%（参考片中位数 2.85%）。满屏奇观那几帧超过 4% 是正常的。
- **静止**：fps 2、192×108 灰度；超过 0.02% 的像素变化超过 4，才算这一帧「在动」。`freezes_over_8s` **必须为空**（CONTRACT §2.5）。`motion_mean_pct` 只报告（3.7–7.3%）。
- **响度**：ebur128 的 I / LRA / Peak。
- **注意**：每 5 秒抽一帧可能漏掉奇观镜头。弱关系的满屏那段是另外逐帧查的。
- **人工总闸**：把 `vs_reference.jpg` 和 `3_第三版资料\学习\对照\全片每5秒_参考_信息论.jpg` 并排看。标准是：没看过的人分不出哪条是我们的。

**C. `tools\v4_stutter.py <video> [--from s] [--to s]`**（CONTRACT §0.9：成片要过这一关）
- 方法：每帧缩到 240×135 灰度，d = 相邻两帧的平均绝对差。
- `FREEZE`：连续 ≥2 帧 d < 0.02，而前后各一秒的运动中位数 > 0.3。**必须为 0。**
- `POP`：d > max(6 × 前后 30 帧的局部中位数, 3.0)。有意的 POP（片名闪光、快淡、快推）可以留，但每个都要在自检记录里写明原因。快淡在报告里会表现为一串小 POP，这是正常的。
- **硬静音那一帧**，画面必须做一个看得出是故意的动作：
  - 峰终：干净地切；主句定住，尘埃继续飘（Backdrop 走真实时间）；静音段内 d ≥ 0.148。
  - 弱关系：0.2 秒 (1−x)² 曲线淡到只剩一条金线。
  - 赫布：7 帧线性淡到 5%，闪烁和尘埃继续动。

**D. 响度和混音**
- 两遍 loudnorm，I = −16 LUFS，TP ≤ −1.5 dBTP，LRA 7–10 LU（CONTRACT §0.6）。
- 第二遍的 `normalization_type` 要是 `linear`。如果线性增益会让 TP 超标，ffmpeg 会悄悄退回 `dynamic`。对策：前面加 `alimiter`（峰终 `limit=0.5`，弱关系 `0.32`），或者调低 boom 的增益（弱关系 0.6–0.7）。
- AAC 编码会让真峰值抬高 0.04–0.3 dB，所以 mix.wav 的目标定在 −1.8 到 −2.0 左右（赫布第二遍用 `TP=-2.0`）。
- 实际结果：峰终 −16.1 / 7.7 / −1.8，弱关系 −16.0 / 8.3 / −1.9，赫布 −16.0 / 8.1 / −2.0（I LUFS / LRA LU / TP dBTP）。
- 硬静音时长：**一般 2–3 秒，最震撼的那一拍用满 3 秒**（用户 10-12「震撼那一拍停久一点」，峰终就是 3 秒；CONTRACT 里的 1–1.5 秒已经过时，见 `规则清单.md` §7 第 20 条）。
- 最低门槛：数字零 ≥1.45 秒，低于 −60 dBFS ≥1.5 秒；`silencedetect n=-60dB:d=0.4` 只报出计划中的那一段。
- 片名的重击要是全片最响的瞬间之一；片尾一段最响或接近最响。

**E. 审稿留下的声音验收标准**（赫布 `audio_check.py <wav|mp4> [cue.json] [--ref mix.wav]`）
- 模拟手机外放，响度下降 ≤3.5 LU（赫布 2.4–3.0）。
- 60–250 Hz 能量占比 ≤ −3 dB（弱关系）。
- 铺垫段比落点段至少低 6 LU。
- 开场响度在 I 的 ±2 LU 以内。
- 每一声钟或钢琴音，在自己的频段里比前 0.5 秒高 ≥15 dB；起音误差在 ±50 ms 以内。
- 钟声 8 kHz 以上的峰值 ≤ −22 dBFS；起音处单个采样的最大跳变 ≤0.2（赫布）。
- 不能有超过约 5 秒的段落低于 I − 3.5。

**F. 每一声叮都要落在画面重点上**（CONTRACT §0.10）
- 弱关系的 `out\v4\ties\tools\hit_visual.py <video> <cue.json>`：比较每个 hit 前后各 0.2 秒的两帧，报告变化最大的 64×36 方块（排除字幕区），然后去看抽出来的帧。
- 峰终测过每声钟在自己频段（B6 1976 / G6 1568 Hz ±40 Hz）里比前 0.3 秒高 13–17 dB。

**G. 画面验收**（赫布 `measure_picture.py`）
- 不能连续 ≥1.5 秒「几乎全黑」（亮度高于 50 的面积低于 0.05%）。约 3 秒的硬静音如果整段淡到近黑，会被这条报出来：画面最好像峰终、弱关系那样留一个定住的主角或一条金线；真要全黑，就在自检记录里写明是计划内的。
- 不能有「幻灯片」段（变化 <0.15% 持续 ≥4 秒）。
- 不能有单帧跳变（d > 1.2 而局部中位数 < 0.15）。

**H. 规格**（CONTRACT §0.3）：1920×1080，30 fps，H.264 crf 16–18，AAC 320k；yuv420p、bt709、tv range。帧数 = round(时长 × 30)（峰终 8742，弱关系 8556，赫布 8634）。

**I. 人工检查**
- 每个改动的时刻都抽全尺寸帧，一张张看（用 Read 打开图片）。
- 字幕以外的汉字每帧 ≤20 个，多数帧 ≤8 个。
- 底部 120px 里没有动画焦点。
- 每个人名、年份、数字都在事实核查.md 里。
- 「Opus 5.5」只出现在最后 2 秒。
- 交付说明要写明每部片都经过「一个没参与修改的人独立核查过」。

## 10. 已知的坑

**制作方面**
1. 不要手改 JSON。改了生成脚本就重新生成，渲染前确认重新生成的文件和预期一致。
2. 每次重新混音后都要重新渲染。弱关系就被查出过 P0：「成片过期、mix 比 music 旧」。
3. **score.py 所有随机都来自同一个带种子的随机数发生器**，所以把某个 cue 拉长，之后的混响和随机音符都会变；改 `dur` 也会改变波形，虽然听起来差不多。改完要重听整段，并告诉用户哪些地方的声音可能和上一版不完全一样。
4. `intensity` 也会放大钟声：同样的钟声增益，在高强度段里会响约 5 dB（赫布 §9.4）。
5. Remotion 的 AAC 比 mix.wav 晚 42.7 ms。要么不加 `-shortest` 重新封装，要么把画面上的切点提前 1–2 帧来遮住（弱关系的做法）。
6. kit 的 `ParticleText` / `useTextPoints` 冷启动时会采到错误的字体，要先等字体就绪。
7. 每 5 秒抽一帧的 v4_qa 会漏掉短奇观，关键段要逐帧看。

**Windows 和 shell 方面**（10-12 实际踩过）
1. **bash heredoc 里写 Windows 路径会出错**：`\24` 被当成了控制字符。需要多行 Python 时，用 Write 工具把脚本写成文件再运行，不要用 heredoc。
2. **这个 shell 里 grep 的中文方括号表达式不好使**。中文正则一律用 Python 写。
3. **渲染前把 TEMP/TMP 指到 `D:\tmp\v4<slug>`**（C 盘小），渲染完删掉 `remotion-webpack-bundle-*`；`D:\tmp\v4qa_*` 也要定期清理。
4. **ffmpeg 的 `-shortest` 会截掉最后几帧**，封装时不要加。
5. **AAC 带来约 42 ms 延迟**，见上面第 5 条。
6. PowerShell 5.1 里没有 `&&`，用 `; if ($?) { … }`。双引号字符串里，变量后面紧跟中文要写成 `${OLD}_手机预览` 这种形式，否则中文会被当成变量名的一部分。
7. 直接敲 `python` 可能打开 Microsoft Store 的占位程序，一律写 `D:\conda\envs\d2l\python.exe`。
8. **往这个 shell 打印中文会报 cp1252 `UnicodeEncodeError`**（比如查 subs.json），加了 `-I` 以后 `PYTHONIOENCODING` 也不起作用。临时打印用 `python.exe -X utf8 ...`，或者把结果写进 UTF-8 文件再用 Read 看。

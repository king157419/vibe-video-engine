## 1. 选题提案

放在 `<n>_第<n>版资料\`。文件名还没有先例，建议用 `选题提案_MMDD.md`。

```markdown
# 第<n>版选题提案：<一句话说明>

> <日期>。先讨论，定了再写剧本。查重依据：`4_第四版资料\片单.md` 末尾的「账本」。
> 这次贴的时令 / 热点：<如：上海入秋降温；热点来源：<工具或链接>>

## 选题 1《<片名，2–4 字>》

| 项 | 内容 |
|---|---|
| 抖音标题 | Vibe知识大赏｜《<片名>》<一句钩子，不剧透揭晓> |
| 有名字的大想法 | <学名> · <人名> · <年份>（<一句话说清它说的是什么>） |
| 为什么这几天的人想看 | <季节 / 天气 / 热点，具体到这一周> |
| 开头 10 秒，观众身上发生什么 | <此刻发生，不是回忆，也不是只提一个问题；观众做完这个动作，就亲身经历了这个概念> |
| 醍醐灌顶的那一下 | <「原来如此」的瞬间：机制是什么，用哪个画面讲透> |
| 讲透：原理 → 例子 | <先讲原理，再举 1–2 个生活例子；关键数字用对比说，比如「只暖了 1 度」> |
| 升尺度 / 大反转 / 满屏奇观 | <一个 → 一群 → 一生>；<反转是什么>；<满屏画面是什么> |
| 文化引用 | <原文>（<出处>）。适用范围：<和概念一样普遍吗？是 / 否，为什么> |
| 落点（一种看法，能抄进弹幕） | 「<一句>」 |
| 形式即内容的梗 | <片子自己怎么演示这个概念> |
| 和做过的哪里不一样 | 学科 <>、入口 <>、母题 <>、骨架 <>、主色 <>（对照账本） |
| 风险 / 待核 | <拿不准的事实，可能让人觉得冷门的地方> |

## 选题 2 …（格式同上，一共 2–4 个）

## 我的推荐和理由
<推荐哪个，为什么；其余几个为什么不推荐>

## 想和你讨论的
1. <具体问题，比如开场二选一、引用二选一>
2. …

## 讨论结论（讨论后补）
- <定了哪个题、开场怎么做、引用用哪句、落点句>
```

## 2. Kimi 写作任务书（中文）

底稿是 `5_第五版资料\文案对比\任务书.md`，用户更喜欢它产出的文案。**任务书一律用中文写**：Opus 的中文读着像翻译，有一部分原因就是我们以前给的指令是英文。

调用方式：
```
D:\conda\envs\d2l\python.exe D:\desk\claudex\24\video-engine\tools\kimi.py --prompt <任务书.md> --out <raw_kimi.md> --model k3 --effort max
```
- 默认 `--effort max`。第一次盲比用的也是 `max`（见 `谜底_比完再开\谜底.md`）。
- key 是 `D:\desk\claudex\24\.env` 里的 `KIMI_API_KEY`，不要显示出来。
- 推理过程会另存为 `<out>.reasoning.md`。

```markdown
# 任务：给抖音 #vibe知识大赏 写一部短片的文案

## 这个类型是什么

抖音上近期很火的「vibe知识大赏」，是用 AI 写代码生成的知识短片，每部 4–5 分钟。

- **画面**：近黑的底，光是主角，一屏只讲一件事（一个发光的点、一条线、一张网、一句话）。
- **文字**：没有旁白，所有文字都靠字幕，一句一句出现。情绪靠配乐撑起来。
- **内容**：讲一个有名字的大想法，带人名和年份。从生活里的一个小瞬间进去，最后回到生活，落在一种看世界的方式上。
- **观众**：刷短视频的普通人，注意力随时会走。

## 观众给过的意见（必须遵守）

1. 用白话和形象的画面，把一件事讲透。先讲原理，再举例子，不能点到为止。
2. 关键数字用对比说出来。比如不要只写「14 度」和「15 度」，要写「只比刚才暖了 1 度」。
3. 前面出现过的东西，后面再提到时，画面要把它拉回来，不能指望观众还记得。
4. 开头 10 秒，要让观众身上真的发生一件事，比如猜一个数、等一个东西、被吓一下。只提一个问题不算。
5. 不要课堂腔：不出现「知识点、记住、注意、正确答案、选项」这类词，也不出 A/B/C 选项。
6. 不要自造术语。非要用一个新说法，先用一个具体的画面让人明白它是什么。
7. 片尾不要写「由 AI / Claude 生成」之类的话。
8. 【新增】全片要有一处文化引用（诗词、古文、名人原话），用在能「升华」的地方。引用的适用范围要和概念一样大：讲的是普遍现象，就不能用只适用于某一国、某一地的话。
9. 【新增】要戛然而止的句子，用破折号或冒号，让人看出是故意停的。
10. 【新增】最震撼的那一句之后，留出 2–3 秒的空白，并在秒数里写出来。

## 现在的时间

<年 月 旬>。<城市>已经<季节和天气>。题目要和最近的天气、季节或热点贴近。

## 剧本骨架（照这个结构写，画面栏可以改得更好）

（写整部文案时才有这一节。把 SKILL 第 2 步的节拍级骨架贴在这里：章节、每个节拍的画面主角和大致秒数、片名卡、反转、满屏奇观、2–3 秒的硬静音、引用那一章、叮的位置、落点句。）

## 你要交的东西

### 一、<N> 个选题（只在需要选题时保留这一节）
每个选题写清楚：片名（2–4 个字）、抖音标题（一句钩子）、背后的大想法（叫什么、是谁提出的、哪一年）、为什么这几天的观众会想看、开头 10 秒观众身上发生什么。

### 二、一部完整文案

题目固定为：**<题目：一句话>**。<如果是盲比，加一句：另一位作者也写这个题，题目相同才好比较。>
【新增，可选】我们已经讨论定的思路：<开场 / 醍醐灌顶的那一下 / 反转 / 引用 / 落点>，请照这个写。

要求：
- **时长**：<4–5> 分钟。
- **格式**：按章节写，每一行是一句字幕，格式为 `秒数 | 中文字幕 | 画面`。
  - 中文字幕每句不超过 20 个字，不用写英文。
  - 「画面」一栏用一句话说清这时屏幕上是什么。
- **片名**：写清楚片名在哪里出现。片名要等开场的体验过去之后再出来。
- **章节递进**：每章往上走一级，后一章要用到前一章讲的东西。
- **金句**：全片最多 3–4 句，放在章尾。
- **奇观**：中间要有一处全片最震撼的满屏画面，写清楚它是什么。
- **结尾**：回到开头那个瞬间，落在一句看法上。
- **事实**：人名、年份、实验、数字都必须是真的。文案最后列一张表，写出每条事实和它的出处；拿不准的标「待核」。

只交这<两>样东西，不要写别的说明。
```

**合格的 Kimi 稿应该长这样**（第一次盲比里「甲」的格式）：
- 开头几个要点：`总时长`、`**片名位置**`、`**奇观**`、`**金句**：共 n 句，以 ★ 标出，均在章尾`。
- 章节标题：`## 第一章 · <章名>（0–20 秒）`，下面接一张 `| 秒数 | 中文字幕 | 画面 |` 表。
- 最后一节 `## 事实与出处表`，列为 `| 片中事实 | 出处 / 依据 | 备注 |`，备注填 确凿 / 待核 / 体验性事实。

**英文字幕**由 Opus 在 Kimi 定稿之后翻译。片子里仍然是中英双语。

### 盲比的文件夹结构（样例：`5_第五版资料\文案对比\`）

```
文案对比\
  任务书.md                 两位作者用的同一份任务书
  甲.md                     第 1 行「# 甲」，空一行，第 3 行「> 和「乙」用的是同一份 `任务书.md`。全文没有改动。」
  乙.md                     第 1 行「# 乙」，空一行，第 3 行「> 和「甲」用的是同一份 `任务书.md`。全文没有改动。」
  谜底_比完再开\
    raw_kimi.md, raw_kimi.reasoning.md, raw_opus.md, 谜底.md
```
- 甲、乙谁是谁要随机分配，并且只写在 `谜底.md` 里。
- Claude 不给两份稿打分，交给用户或独立评审来判。
- 要注意文件大小也会泄底：调研时就从字节数推出了甲是 Kimi。【建议】交给用户之前，把两份稿的头部格式统一。

## 5. 审稿记录.md ＋ 自检记录.md 的提纲

```markdown
# 《<片名>》审稿记录（第一稿 → 第二稿）

> <日期>。三位审稿人：genre（像不像这个类型）、facts（对抗式事实核查）、user（用户视角：用户本人 / 普通观众）。三位的结论：<改 / 重写>。
> 规矩：P0、P1 全改；P2 酌情。事实类意见先自己重查一遍网页再改，结果写在 `事实核查.md`。没有照审稿人原话改的，下面写了理由。
> 这一稿改了：`剧本.md`、`<生成脚本>.py`、`public/v4/<slug>/{subs,cue,<meta>}.json`、`事实核查.md`、`发布文案.md`。
> 片长 <旧> → **<新>**；字幕 <旧> 句 → **<新> 句**。「L<n>」指第二稿的编号，「原 L<n>」指第一稿。

## 0. 一眼看改了什么 / 字幕编号对照
```

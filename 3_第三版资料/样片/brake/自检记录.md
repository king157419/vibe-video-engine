## 1. 做了什么

### 1.1 声音

- **旁白**：直接用审稿后已合成好的 `public/v3/brake/audio.mp3` + `captions.json`（审稿时用的就是本步指定的命令：edge-tts `zh-CN-YunxiNeural`、`--rate=-4%`、`--max-line 22`）。核对过：去掉标点后 551 个字和 `script.txt` 逐字一致，42 行字幕每行不超过 22 字，时长 167.29 秒。没有重新合成——edge-tts 每次合成的停顿会有几十毫秒的差别，重合成会让分镜表里的秒数全部作废，内容又完全一样。
- **配乐**：`3_第三版资料/样片/brake/make_audio.py` 一条命令完成：
  1. 从 `captions.json` 取每段第一句的开始时间当 `--marks`（0, 24.07, 40.80, 50.07, 77.01, 93.04, 107.77, 120.75, 141.46, 156.24，和分镜表 §2.3 一致），调用 `tools/music_synth.py --key D --mode minor --mood calm --bpm 72 --density 0.25 --dur 169.9`。
  2. 配乐静音：**13.87–24.07**（黄车定格 → 押注 3 秒 → 揭晓 42 → 再静 1.5 秒；定格时刻用和画面代码同一个公式算：“刚好停住”开始 + 0.13 s + 0.704 s ÷ 0.6）；**91.53–93.04**（第二次“42码”之后）。终局喷字那 2.5 秒配乐不停（分镜要求）。
  3. 混音：配乐按实测响度压到比旁白低 **20.0 LU**（旁白 −24.2 LUFS，配乐增益 −28.3 dB）；整体抬到 −15 LUFS 后用限幅器（−2.2 dBFS）压住偶发峰值。实测 `mix.wav`：−15.04 LUFS，真峰值 −2.07 dBTP。
  4. 没有任何音效：没有引擎声、刹车声、滴漆声、沙沙声。成片静音检测（−50 dB、≥1 秒）只出现在 18.7–21.8（押注 3 秒）、22.5–24.2（揭晓后）、91.6–93.2（第二次 42 之后）和片尾淡出。

- **数字只有一个来源**：画面上所有数字都从 `public/v3/brake/numbers.json` 读（由 `numbers.py --json` 写出），包括漆点位置和速度、42、35、4.2 米、10 米、0.7 秒、0.53/0.07 秒、2.78 米、72/60/56%、33 米、×2、6 个点、1/4 等。本步给 `numbers.py` 加了几项画面要用、原来没写进 JSON 的量（`cards.ebike_brake`、`cards.split`、`cards.phone_dots`、`quiz_dots`），用脚本比对过：原有键的值一个没变。
- **确定性**：没有 `Math.random` / `Date.now` / CSS 动画 / 计时器；颗粒用 mulberry32 固定种子；“??”乱跳的数字由帧号决定。
- **字体**：只用 `ensureFonts()` 加载的思源黑体（路面喷字 900 + 纵向拉长，读数 700 等宽数字，标签 500–700）。没用霞鹜文楷（这条刻意不走手绘）。
- **颜色一色一义**：白 = 50 码（点、读数）和路面标线/喷字；黄 = 60 码；灰 `#8b8f96` 只给错误直觉（A 卡、放样线、“该剩 25”、“按米”）；红只给 60 码撞线的“42”和越线那一小段（读数、俯视越线段、曲线终点、终局图，都是同一个意思）。

### 1.3 自检流程（两轮半尺寸草稿 + 多次抽帧）

1. 先用 `stills.mjs`（一次打包、批量抽帧）抽了约 60 张关键帧逐张看，按问题改了 4 轮：
   - 开头：近处沥青颗粒成块 → 限制颗粒最大尺寸；驾驶视角里漆点在引擎盖边上是一摊白斑 → 改成升镜时才露出；右半边“同款车”和假设角标打架 → 角标改三行、标签左移；35 米外的人太小 → 驾驶视角用长一点的镜头（焦距 900 → 升镜中过渡到 685）。
   - 俯视：漆点和分隔虚线挨着、像一串虚线 → 漆点轨迹改到车右侧、贴着路缘实线；人形标志白色压在白色斑马线上看不见 → 加深色描边；车头碰线时盖住人 → 人站进斑马线 1.2 米。
   - 读数停在“5”不到“0” → 停住处那个点在 0.2 s 网格上（tb = 2.0 s），车在 1.984 s 已停，播放时长改成到最后一个点为止。
   - 押注卡压住“刚好停住”和白路 → 卡改落在画面下方空带；A 卡揭晓后只需水平左移。
   - 灰线尺寸标注和 A 卡小字、“每米”喷字互相压 → 两条路共用一根“35 米”尺寸线、喷字时收起；35 米处的读数“0/10”和“共 −50”移到斑马线右边。
   - 刷子的杆横压在漆点上 → 改成斜杆，从右上进、往右下退。
   - 雨天读数“雨天”压在斑马线上 → 左移；湿反光带像 UI 条 → 改成两头尖的哑光细带。
   - ③b 拉镜后②的括号压住角标 → ③b 开始时收起括号（小结行接着当残影）。
   - 抛球：“−3.5”标签和“每 0.1 秒一个点”打架 → “−3.5”移到球列右边；车那排点横向放大 1.7 倍。
   - 边界卡 3：反应段用 42% 白看起来是灰色（灰是错误直觉的颜色）→ 改成空心框。
2. **草稿 1**（半尺寸全片）：1 fps 印样 6 张逐张看；freezedetect 无 ≥ 6 秒静止；静音点和响度正确。按印样再改：24–32 秒画面几乎不动 → 加“约 1/4 的回答”四格条、算式逐步写出“60 − 50 = 10”、A 卡在“剩10码”再跳一下；图表放大到 6 px/码；“按米”“按秒”加底板；雨天镜头下移居中；边界卡下移。
3. **草稿 2**：同样检查一遍，再抽全尺寸帧检查文字压线：③c“刹车路只用了一半”压在斑马线上 → 分两行放到斑马线右边；②的灰色刹车段直线拖到 ③c → 提前收起；“60 − 50 = 10”被黄路路缘线穿过 → 移到 A 卡右侧、② 开始时收起；黄路压暗时红色越线段没跟着压暗 → 修正；滑动的“1 米”小括号和刻度数字打架 → 移到线下方。
4. **终版**：全尺寸渲染后再出每 2 秒一帧的印样、跑 freezedetect / silencedetect / 响度（§4）。

## 3. 和方案 / 分镜表的偏离及理由

| # | 分镜/方案 | 实际 | 理由 |
|---|---|---|---|

## 5. 已知问题

1. **配音是占位的 edge-tts**，语气偏平；换真人配音时要重新跑 `captions.json`（锚点按词找，画面会自动跟上，但让位停顿的长度要再看一遍）。
2. **E 文件清单第 23 条没做**：要找 1–2 个没看过的人看成片，再问分镜表 §3 第 23 条的三个问题。
3. **撞题核查没做**（事实核查第 12 条）：发布前要在抖音、B 站站内人工搜。
4. **押注没有“取平均”选项**（审稿记录 §5-1）：选“取平均”（55 码）的观众会去选 C，得不到预测误差。按审稿建议这一版不改。
5. 升镜中间有约 0.15 秒站立人形和平躺人形同时可见（交叉淡化）。
6. 终局开头 2.5 秒里，4 张边界卡的缩略图上的字小于 36 px（只是过渡，留题出现时就淡出）。
7. 抛球段画面左上大片留空；图表段“按米”是灰字压在深色底板上，对比度偏低（灰色是规定的“错误直觉”色）。
8. 16:9 横屏在手机竖着看时整体偏小；漆点半径 8 px（全尺寸），竖屏小窗里会比较细。
9. 片尾没有单独的关注引导卡，最后 3.5 秒停在终局图 + 留题上（方案没有要求）。
